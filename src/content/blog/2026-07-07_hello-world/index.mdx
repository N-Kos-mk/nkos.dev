このブログを始めました。

## なぜ始めたのか

作った技術的なプロジェクトは [/works](/works) の方にまとめればいいので、ブログの役割はそこと切り分けたいと思っていました。

一方で、思いついたことを短文でぽんぽん投げるようなスタイルは、個人的にはブログとして好きではありません。断片的な雑書きが増えるほど、あとで読み返したときに何を考えていたのか追いづらくなるからです。

なので、このブログでは

- 作った技術のプロジェクトは書かない（そちらは works に任せる）
- 雑な短文を量産しない
- 主張や趣旨をはっきりさせたうえで、ちゃんと記事として書く

という方針でやっていこうと思っています。

## 個人サイトでホストする意味

せっかく自分でホストしているブログなので、既存のブログサービスにはないような機能を足せるのも魅力の一つです。

このブログは Markdown ではなく MDX で書いていて、記事の中に直接 React コンポーネントを埋め込めます。たとえばこの回転寿司もその一例で、記事本文の中からそのままインタラクティブなコンポーネントを呼び出しています。

<div style={{ textAlign: 'center' }}>
  <RotationSushi size="4rem" />
  <p style={{ opacity: 0.5, fontSize: '0.85rem', marginTop: '0.5rem' }}>This is rotation sushi.</p>
</div>

こんな感じで、文中にも気軽に置けます。

## 実装の試行錯誤

ブログ機能自体も一発では決まらず、何度か構成を変えました。せっかくなので過程を記録しておきます。

### 最初の構成はボツ

最初は `src/data/posts.js` に記事データをオブジェクト配列で定義し、独自パーサで Markdown 風に変換していました。しかし記事が増えるほどファイルが肥大化し、画像もアセットパイプラインを通せず、本文に React コンポーネントも埋め込めない。すぐに詰みました。

### MDX 構成への移行

そこで `@mdx-js/rollup` を使い、記事ごとにディレクトリを切る構成に変更しました。

```
src/content/blog/
  YYYY-MM-DD_slug名/
    index.mdx       ← 記事本文（Markdown + JSX 混在可）
    cover.*         ← サムネイル（任意）
    image.png       ← 記事内画像（任意）
```

`vite.config.js` では MDX プラグインを React より前に `enforce: 'pre'` で登録する必要があったのが地味なハマりポイントでした。

記事の収集は `import.meta.glob` でディレクトリを走査し、日付降順にソートしています。ディレクトリ名に `YYYY-MM-DD_` のプレフィックスを付けたことで、ファイルシステム上でも自動的に時系列順に並ぶようにしています（URL 上のスラッグにはこのプレフィックスは含めていません）。

### UI も何度か作り直した

一覧ページは縦並びリスト → 2 カラム → 3 カラムと変遷し、最終的には excerpt を非表示にしてサムネ・日付・タイトルだけのすっきりしたカードに落ち着きました。サムネあり・なしで比率が揃わず崩れていた時期もありましたが、両方 `16:9` に統一して解決しています。


## おわりに

というわけで、このブログは

- 主張のある記事だけを書く
- 個人サイトならではの機能を使っていく

という方針でやっていきます。よろしくおねがいします。
